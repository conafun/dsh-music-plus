# 网络电台功能 · 设计定稿（as-built）

> 目标：在 dsh-music-plus 之上新增「网络电台」——内置一份 CC0 电台库，可按风格浏览/收听，
> 也可自己添加单台电台或整批导入外部电台源（兼容主流清单格式）。**全部界面只放在
> DSH 设置页新增的「网络电台」一页里，播放面板与播放条不新增任何东西。**
>
> 状态：已实现。单测见 `test/radio.test.js`（解析器 + Host 库）与 `test/client.test.js`
> （设置页渲染/交互回归）。

---

## 1. 已确认决策

| 项 | 决定 |
|---|---|
| 界面位置 | **只在设置页**：`settings.section` 新增一页（`id: 'music-radio'`，label「网络电台」）。播放面板/播放条**零新增** |
| 内置内容 | 内置 **conafun/recommended-radio-streams** 的快照（**CC0 1.0**，可自由内置、无署名义务）：16 个风格、432 台 |
| 分类 | 直接沿用上游的 16 个风格分类（数据里保留英文 slug，UI 显示中文名），另支持自定义风格与给单台打标签 |
| 自己添加 | ① 手填单台（名称/流地址/主页/风格/标签）② 整批导入外部源（M3U/M3U8、PLS、XSPF、ASX、radio-browser JSON） |
| 持久化 | Host 端 `~/.dsh/dsh-music-plus-radio.json`（沿用 `dsh-music-plus-*.json` 模式） |
| 播放 | 复用现有 `<audio>` 引擎与播放条；电台是直播流：**没有进度、不能快进**，断流自动重连 |
| agent | `music_play_plus` 增加 `radio` / `radioCategory` 参数（「放个爵士电台」） |

## 2. 为什么界面只在设置页

电台的交互是「一次配置、长期收听」，与「播放中切歌」不是一类操作；插件已有的
「本地音乐 / 播客 / 系统配置」三页签是**播放控制**面，塞进第四个页签会把播放面板变成
配置抽屉。因此：**设置页负责「有什么台」，播放条负责「在放什么」**。

播放条本身一行未改：点电台的 ▶ 之后，播放条照旧显示当前名称（这里是台名），
进度细线因为没有 duration 自然停在 0——这不影响任何既有行为。

## 3. UI 结构（设置 → 网络电台）

```
共 432 台 / 16 个风格（显示 432 台）   🟢 12 · 🔴 3 · ⚪ 417   内置库 ee4dc39   [刷新]
[搜索电台名/风格/主页………]  [检测当前列表] [检测全部] [停止]
(全部 432) (★收藏 5) (电子 48) (爵士 · 布鲁斯 33) … (已隐藏 2)
┌ 电子 · 48 台 ─────────────────────────────────────────────┐
│ ● ▶ NTS - Channel 1  · UK   [MP3]           主页 ☆ ✎ ✕ │
│ ● ▶ HLS Only         [需 HLS]               主页 ☆ ✎ ✕ │
├ 爵士 · 布鲁斯 · 33 台 ────────────────────────────────────┤
│ ● ▶ Jazz24 · US  [MP3 · 256kbps]            主页 ★ ✎ ✕ │
└───────────────────────────────────────────────────────────┘
▸ ＋ 添加 / 编辑电台
▸ 电台源（内置库 / 外部源）
▸ 风格管理（16）
```

- **状态点**：🟢 在线（含延迟）／🔴 离线（含原因）／⚪ 未检测；hover 显示「多久之前检测的」。
- **探活**：分批（每批 12 个并发）请求，界面显示 `已检测/总数` 与在线数，随时可停。
- **HLS(.m3u8)**：标「需 HLS」并置灰不可播（浏览器原生 `<audio>` 播不了，本版不引入 hls.js）。
- **清单型(.pls/.m3u)**：标「清单」，点播时由 Host 解析出真实流地址并按台缓存。
- **删除语义**：手填电台真删；内置/外部源电台只**隐藏**（否则刷新又回来，用户会以为没生效），
  隐藏的台在「已隐藏」里可恢复。
- **风格管理**：显示/隐藏、改名、↑↓ 排序、删除自定义风格（台会回到「未分类」，不删台）。

## 4. Host 端

### 4.1 两层状态模型

```
内容层（可再生成）             用户层（不可丢）
├ 内置快照 lib/radio-data.json  ├ favorites[]      收藏
├ 外部源 sources[].stations     ├ overrides{id:{}} 改名/改分类/标签/隐藏/探活结果/已解析地址
└ 手填电台 custom[]             └ categories[]     自定义风格与对内置风格的覆盖
```

两层用**电台 id** 连接。电台 id = **流地址的 hash**（`st-xxxxxxxx`，见 `lib/radio.js`
的 `stationId`），所以：

- 「从 GitHub 更新内置库」「刷新外部源」只是替换内容层，用户的收藏/隐藏/改名**按 id 全部保留**；
- 上游改版、分类重排、台名微调都不会丢用户数据；
- 手填电台与内置电台重复（同流地址）时按地址去重，**手填优先**。

### 4.2 路由（都挂在既有的 `/dsh-music-plus` 前缀分发器下）

| 路由 | 方法 | 说明 |
|---|---|---|
| `/radio` | GET | 设置页快照（分类 + 电台 + 源 + 统计） |
| `/radio/station/add` | POST | 手填单台 `{name,url,homepage?,categoryId?,tags?}` |
| `/radio/station/update` | POST | `{id,name?,homepage?,categoryId?,tags?,hidden?}`（内置台写进 overrides） |
| `/radio/station/remove` | POST | 手填台真删；内置/外部源台隐藏 |
| `/radio/favorite` | POST | `{id,fav}` |
| `/radio/category/add｜update｜remove` | POST | 新建自定义风格 / 改名·隐藏·排序 / 删除自定义风格 |
| `/radio/source/add｜remove｜refresh｜reset` | POST | 加外部源 / 删源 / 刷新（内置库=重拉上游 README）/ 恢复插件内置快照 |
| `/radio/probe` | POST | `{ids?}` 批量探活（并发 6、单台 6s 超时），结果写回 overrides |
| `/radio/prefs` | POST | `{prefs:{lastStationId,hideDead}}` |
| `/radio/resolve` | GET | `?url=` 把 .pls/.m3u 清单解析成真实流地址（按台缓存 7 天） |

**写操作一律回传整份快照**，所以设置页每次操作只需要一次往返就能整体刷新。

### 4.3 解析器（lib/radio.js，零依赖）

| 格式 | 说明 |
|---|---|
| M3U / M3U8 | `#EXTM3U` / `#EXTINF`，兼容上游的 `# Group:` + 每台 `# Homepage:`，也兼容 IPTV 的 `group-title=` |
| PLS | `FileN=` / `TitleN=` |
| XSPF | `<track><title>/<location>/<annotation>` |
| ASX / WAX | `<entry><title>/<ref href>` |
| README 清单 | 上游仓库的 `- [台名](主页): [Stream](流地址)` 格式（2~4 级标题=分类，多路流自动拼频道名，识别 `*(down …)*`） |
| radio-browser JSON | `url_resolved` / `tags` / `codec` / `bitrate` / `country` |

解析不出格式时**回退成单条直链电台**——用户直接粘一条 mp3/aac 流地址也能加。
`detectFormat()` 同时看后缀、Content-Type 与正文特征。

## 5. Web 端（lib/client.js）

- **引擎**：`scope` 增加 `{ kind: 'radio', id }`（id = `'all' | 'fav' | 分类 id`），
  接入点与播客同构——`resolvePlayable()` / `activeIds()` / `scopeKey()` / `startPlay()`；
  列表顺序与设置页**完全一致**（分类顺序 → 台名），保证 next/prev 和眼睛看到的一致。
- **直播语义**：`onended` / `onerror` 在电台范围下走 `radioReconnect()`
  （1/2/4/8/12 秒退避，5 次失败自动切下一台）；`savePlayback()` 对电台直接返回，
  绝不覆盖本地音乐/播客的断点续播；`stop()` 会掐掉重连计时器。
- **不新增前端**：没有新的页签、没有新的播放条按钮。电台的播放状态复用既有播放条。

## 6. 边界情况

1. **断流**：自动重连；仍失败切下一台（电台没有「播完」这回事）。
2. **HLS 台**：置灰 + 提示，不静默失败（要支持需引入约 1MB 的 hls.js，见下）。
3. **上游大改**（README 结构变了）：解析出 0 个分类时**拒绝覆盖**并保留原内置库。
4. **重复台**：按流地址去重，手填 > 内置 > 外部源。
5. **状态文件损坏/不可写**：退化成空用户层，内置库照常可用（持久化尽力而为）。
6. **CORS**：电台流直连播放不需要 CORS；只有频谱（captureStream tap）在未开 CORS 的源上可能不显示，**播放不受影响**（与播客一致）。
7. **HTTP 源**：DSH GUI 在 `http://127.0.0.1` 下，所以 http 流不会被混合内容拦截；若将来用 https 提供服务，http 流会被浏览器拦掉。

## 8. 明确不做（本版）

| 项 | 原因 |
|---|---|
| HLS(.m3u8) 播放 | 需要 hls.js（约 1MB）或自建分片播放器；12/432 台受影响，先置灰标记 |
| ICY「正在播放曲名」 | 需要 Host 保持长连接读 `icy-metaint` 元数据块；探活通道已具备类似能力，留作后续 |
| 录音 / 定时关闭 / 电台均衡器 | 与「先把电台放出来」无关，避免一次改太多 |
| 拖拽排序 | 与自建歌单一致：用 ↑↓ 按钮，不做拖拽 |
